## Выполненные задания

### Пункт 1: Создание ветки feature

**Команды:**
```bash
git branch feature          # Создание ветки
git checkout feature        # Переключение на ветку
git branch                  # Просмотр веток
```

**Описание:** Создается новая ветка `feature` от текущей ветки `main`. Ветка позволяет разрабатывать новую функциональность изолированно от основного кода.

**Результат:**
```
* feature
  main
```

✅ Ветка `feature` создана и активна (отмечена звездочкой)

---

### Пункт 2: Просмотр всех веток

**Команды:**
```bash
git branch -a               # Все ветки (локальные и удаленные)
git branch -v               # Ветки с последними коммитами
```

**Результат команды `git branch -a`:**
```
* feature
  main
  remotes/origin/HEAD -> origin/main
  remotes/origin/main
```

**Результат команды `git branch -v`:**
```
* feature 318a96c Добавлен детальный отчет по лабораторной работе №5
  main    318a96c Добавлен детальный отчет по лабораторной работе №5
```

**Описание:**
- `-a` показывает локальные и удаленные ветки
- `-v` показывает последний коммит в каждой ветке
- `remotes/origin/main` - ветка на удаленном сервере GitHub

✅ Видны обе локальные ветки и связь с удаленным репозиторием

### Пункт 3: Создание коммита в ветке feature

**Команды:**
```bash
echo "New feature implementation" > feature.txt
git add feature.txt
git commit -m "Add feature implementation"
```

**Результат:**
```
[feature 64bd55a] Add feature implementation
 1 file changed, 3 insertions(+)
 create mode 100644 feature.txt
```

**Описание:** Создан файл `feature.txt` с реализацией новой функциональности и закоммичен в ветку `feature`. Этот коммит существует только в ветке `feature` и не влияет на `main`.

✅ Коммит создан в ветке feature (хеш: 64bd55a)

### Пункт 4: Возврат на main и создание ветки bugfix

**Команды:**
```bash
git checkout main            # Возврат на main
git checkout -b bugfix       # Создание и переключение на bugfix
```

**Описание:**
- `git checkout main` - переключение обратно на основную ветку
- `git checkout -b bugfix` - комбинированная команда, эквивалентная:
  ```bash
  git branch bugfix
  git checkout bugfix
  ```

**Результат:**
```
Switched to branch 'main'
Switched to a new branch 'bugfix'
```

✅ Создана ветка bugfix от main для исправления ошибки

### Пункт 5: Создание коммита в ветке bugfix

**Команды:**
```bash
echo "Bug fix implementation" > bugfix.txt
git add bugfix.txt
git commit -m "Fix critical bug"
```

**Результат:**
```
[bugfix 152a96e] Fix critical bug
 1 file changed, 3 insertions(+)
 create mode 100644 bugfix.txt
```

**Описание:** Создан файл `bugfix.txt` с исправлением критической ошибки и закоммичен в ветку `bugfix`.

✅ Коммит создан в ветке bugfix (хеш: 152a96e)

### Пункт 6: Слияние ветки bugfix в main

**Команды:**
```bash
git checkout main            # Переключение на main
git merge bugfix             # Слияние bugfix в main
```

**Результат:**
```
Switched to branch 'main'
Updating 318a96c..152a96e
Fast-forward
 bugfix.txt | 3 +++
 1 file changed, 3 insertions(+)
 create mode 100644 bugfix.txt
```

**Описание:** Выполнено **Fast-forward** слияние - Git просто переместил указатель `main` вперед к коммиту из `bugfix`, так как не было расхождений между ветками.

**Что такое Fast-forward:**
- Простейший тип слияния
- Используется, когда в целевой ветке (main) не было новых коммитов
- История остается линейной, без merge-коммита

✅ Ветка bugfix успешно слита в main (Fast-forward)

---

### Пункт 7: Слияние ветки feature в main

**Команды:**
```bash
git merge feature            # Слияние feature в main
```

**Результат:**
```
Merge made by the 'ort' strategy.
 feature.txt | 3 +++
 1 file changed, 3 insertions(+)
 create mode 100644 feature.txt
```

**Описание:** Выполнено **трёхстороннее слияние (3-way merge)** - Git создал новый merge-коммит, так как ветки разошлись. В `main` были изменения из `bugfix`, а в `feature` - свои коммиты.

**Что такое 3-way merge:**
- Используется, когда обе ветки имеют уникальные коммиты
- Создается специальный merge-коммит с двумя родителями
- История показывает ветвление

✅ Ветка feature успешно слита в main (3-way merge)

✅ График четко показывает структуру ветвления и слияний

### Пункт 9: Удаление веток (опционально)

**Команды:**
```bash
git branch -d feature        # Удаление слитой ветки
git branch -d bugfix         # Удаление слитой ветки
```

**Описание:**
- `-d` (delete) - безопасное удаление, работает только для слитых веток
- `-D` - принудительное удаление (если ветка не слита)

**Примечание:** В данной работе ветки оставлены для демонстрации.

## Типы слияний (Merge)

### 1. Fast-Forward Merge (Перемотка вперед)

**Когда происходит:**
- В целевой ветке (main) не было новых коммитов
- История линейна

**Пример:**
```
До слияния:
main:    A---B
              \
bugfix:        C---D

После слияния:
main:    A---B---C---D
bugfix:              D
```

**Команда:** `git merge bugfix` (автоматически Fast-forward)

---

### 2. 3-Way Merge (Трёхстороннее слияние)

**Когда происходит:**
- Обе ветки имеют уникальные коммиты
- Ветки разошлись

**Пример:**
```
До слияния:
        C---D (feature)
       /
A---B---E---F (main)

После слияния:
        C---D (feature)
       /     \
A---B---E---F---M (main)
                |
            merge commit
```

**Команда:** `git merge feature` (создает merge-коммит M)

## Полезные советы

### 1. Именование веток
```bash
feature/user-auth       # Новая функция
bugfix/login-error      # Исправление ошибки
hotfix/security-patch   # Срочное исправление
release/v1.0            # Релизная ветка
```

### 2. Перед слиянием
```bash
git checkout main       # Переключиться на целевую ветку
git pull               # Обновить с сервера
git merge feature      # Слить
```

### 3. При конфликтах
```bash
# Git покажет конфликтующие файлы
git status             # Посмотреть конфликты
# Отредактировать файлы вручную
git add <файлы>        # Отметить как разрешенные
git commit             # Завершить слияние
```

### 4. Отмена слияния
```bash
git merge --abort      # До коммита
git reset --hard HEAD~ # После коммита (осторожно!)
```
